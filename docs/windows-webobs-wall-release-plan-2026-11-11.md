## 3. 目标架构与不可退让的原则

```text
WebOBS 原生主程序：Qt UI、登录、摄像机目录、Studio、监控墙、系统托盘
                        │
             产品控制适配层与权限/身份校验
                  ┌─────┴────────────┐
                  │                  │
   固定 OBS 原生宿主/产品插件      账号、Registry、配置与按需业务服务
                  │                  ├─ NVR / 归档 / 事件 / PTZ
  OBS Media Source → Scene           ├─ go2rtc / MediaMTX / 网站来源
                  │                  └─ 远程 WebUI / PWA / 现有 Android
     D3D11 原生预览 / 场景投影
                  │
        按需求录像 / 推流 / 远程合成输出
```

### 3.1 单一媒体所有权

- Windows 本地监看只保留一套主要 libobs 媒体引擎，由原生宿主管理 source、scene、preview、program、projector 和必要输出。
- 现有 core 中的认证/控制能力可保留，但原生宿主模式下必须有明确的 control-only/engine-adapter 路径，不能再初始化第二套负责相同监看的 libobs。
- 同一摄像机 Profile 与兼容设置跨场景/窗口共享 source；相同 URL 不是充分共享条件。音轨、过滤器、缓冲、解码和权限差异必须纳入兼容判断。
- 普通 RTSP/H.265 本地监看直接进入 OBS 媒体源，不必经浏览器、WebRTC、常驻外置转码或回环编码再解码。
- 允许确有独立需求的 NVR 原码流录制、不同 Profile 和远程分发建立必要连接；要记录用途，不把合理分支误算成重复解码，也不隐藏相关成本。
- 不通过逐帧 CPU 读回、持续截图、虚假录像或编码来维持画面。诊断像素读取限测试或显式短时诊断。

### 3.2 保留 OBS 优点，产品状态仍由 WebOBS 管理

- 复用固定 OBS 版本的 Media Source、D3D11、场景、变换、裁剪、排序、Studio Preview/Program、转场、投影、音频混音、编码器和输出生命周期。
- 保留可用的原生来源属性、窗口布局/大小控制、全屏/多显示器和常用快捷操作。OBS 优点不等于无条件加载任意第三方插件或绕过产品权限。
- 用户看到的是完整 WebOBS 产品：现有账号、设备库、布局和功能入口可用；不能要求用户同时维护互不相干的 WebOBS 与 OBS 两份摄像机配置。
- 第一版不为了改变外观重写 OBS 渲染/播放器，也不为了赶进度把独立 OBS 窗口简单挂到 Electron 旁边当作最终融合。
- Windows 核心入口为原生程序。复杂业务管理页可先复用本地 WebUI，以受认证的系统浏览器提供；默认监看不需要 Electron 常驻，也不能自动在管理页再播放五路相同媒体。
- 需要内嵌页面/浏览器来源时，仅按需求安装并启用经过锁定的组件；不要重新形成 Electron 与另一套 Chromium 同时默认打包、常驻的结构。
- 原有本地功能仍须能在同一台 Windows 上启用和离线安装。WebUI 复用是实现方式，不是把功能移出产品范围。

### 3.3 控制与媒体隔离，真实执行接线

- 建立明确的 engine adapter：列举状态、应用已授权场景、切换 Preview/Program、打开/关闭固定场景投影、查询输出和正常停机。
- 消息使用类型化、版本化、大小有界的命令；身份取自可信会话和摄像机目录，不接受客户端自报管理员/摄像机绑定。
- 同进程优先直接调用受控产品接口。跨进程选择一个明确方案：有当前用户 DACL 的命名管道，或现有受认证 loopback HTTP。不要同时引入多套重叠控制通道。
- HTTP 保留认证、RBAC、Origin、路径与请求大小限制；命名管道也不能只凭“本机可连”视为授权。不给 renderer 任意命令、文件访问或执行能力。
- OBS 图变更在正确线程执行，明确线程切换、截止时间、取消、错误码、并发冲突和失败回滚。队列排队后不能继续使用已失效授权决定。
- `native-host` 现有授权、目录绑定、快照、规划、备份与执行流应连接真实会话、真实后端、真实 OBS target。纯函数通过和 injected doubles 不代表产品接线完成。

## 5. 认证和原生旁路：产品化的硬要求

当前原生分支可见的关键缺口包括：部分 Dock 动作以空 operator state 拒绝；登录/真实执行未全接线；OBS 自身来源编辑、场景恢复、投影和快捷入口可能绕过产品插件。实现前重新核对，不能简单把 gate 改为 true 放行。

必须完成：

1. 登录和会话绑定接入现有权威账号服务；注销、过期、撤销和权限变化确实影响正在观看与待执行操作。
2. 产品管理的场景集合与普通 OBS 用户 profile 隔离。原型 `config/`、旧正式产品数据和系统 `%APPDATA%/obs-studio` 不相互覆盖。
3. 产品模式在未认证状态不能从保存的 OBS profile 自动恢复受保护 RTSP；仅在 `FINISHED_LOADING` 后禁按钮过晚。必须验证实际启动顺序和首次媒体 I/O 前的控制点。
4. 全量列举并约束来源属性、场景集合切换、导入、最近项目、菜单、快捷键、投影、拖放、自动恢复和可选插件入口。不能存在“插件按钮有权限、原生菜单随便看”的状态。
5. 管理员高级原生编辑可保留，但需要明确管理员授权、重新登记产品身份并触发一致性检查。普通值守账户不能经高级模式获得越权来源。产品之外另行运行的独立 OBS 不属于产品 RBAC 可控制范围。
6. 观看检查针对实际场景所含全部受保护来源，包括隐藏项、嵌套和转换/过滤器依赖。无法确认绑定时拒绝执行并提供可理解的修复路径。
7. 授权与图更新有可验证的新鲜度及执行边界；不能把快照时的 allowed 当长期许可。会话失效到关闭受保护画面的时限应明确并自动化验证。
8. 本机用户可直接读自己的明文 OBS 文件属于需明确的磁盘安全边界。产品不要额外导出 Secret，私有文件采用当前用户 ACL；账号 RBAC 不得被宣传成能隔离同一 Windows 用户下恶意任意程序的安全沙箱。

OBS 上游 checkout 不直接修改。确需上游集成 hook 时采用仓库外置、版本锁定、最小可审查补丁及构建副本方式，补丁失配即失败；更新源码/许可证记录。不能为避免补丁而放弃认证要求。

## 6. 数据模型与旧版本升级迁移

- 现有 Registry、Secret 引用、Scene/Studio schema、账号偏好、设备布局和录像索引是迁移来源。OBS scene collection 是运行时映射，不替代所有产品数据。
- 建立并验证 `cameraId + profileId ↔ product source identity ↔ OBS source UUID`、`sceneId ↔ OBS scene UUID`，保留层级、变换、裁剪、音轨、过滤器、可见性、锁定和引用语义。
- 明确产品规范坐标与 OBS 相对/绝对坐标、画布与输出分辨率、整数/分数 FPS、颜色与音频采样率转换；实际运行时回读，不能只检查写入 JSON。
- 迁移按“读取预检 → 私密备份 → 新目录转换 → 语义校验 → 实际 loader/媒体验证 → 受控切换 → 失败回退”执行。转换前不修改旧数据。
- 当前离线转换器只覆盖受限、明确静音的子集，不能当成完整迁移。补齐声音、多场景、嵌套、过滤器、偏好、账号与 Secret、录像路径/索引及原型配置适配。
- 对不能自动转换的旧数据，给出明确诊断和完整的保留/兼容方案；静默丢弃、重建空项目或要求全部手工重录不通过。
- 迁移可重试、幂等、有版本标记；失败、磁盘满、权限不足、断电中断、部分文件写入和进程崩溃后能识别状态并恢复。文件级备份不被夸大为数据库事务/断电持久性。
- 数据库采用一致性快照/受控停机，避免直接复制活跃 WAL 造成缺数据；恢复验证实际内容和 schema。
- 使用合成旧档案覆盖旧稳定版与支持中的开发版升级路径。涉及用户真实档案的最终试迁移保留到集中验收，不擅自打开/覆盖个人私密配置。
- 未登录不恢复受保护媒体；登录后的恢复也只应用仍有权限的来源，保留被拒项信息，不自动扩大权限。

## 7. 进程、按需组件与安装体积

### 7.1 进程所有权

由原生 Windows supervisor 管理实际需要的组件，使用 Job Object、受控启动参数、私密运行目录、健康检查和分级正常退出。若暂时复用 Python 账号或业务服务，可以保留并计入成本，不为了“无 Python”从零重写所有业务；但 Electron 不再是新默认宿主的生命周期所有者。

每个进程记录：启动者、业务消费者、默认/按需、健康端点、退出条件、录像/远程客户端持续使用时的处理、失败重启预算和崩溃收束。

关闭本地投影不误停录像/远程观看；最后消费者结束后释放不再需要的解码、输出与可选服务。支持明确的“保留后台任务”和“完全退出”，避免无限重启风暴与无人持有进程。

### 7.2 体积目标必须按同一口径验证

分别记录：下载字节数、干净安装逻辑字节数、文件系统分配字节数、首次运行新增数据、完整功能组件总量、可选源码/符号包。比较同一 Windows/文件系统/OBS版本和可比组件，不把 ZIP、安装 EXE 和安装目录混比。

核心本地监看安装体积目标：不高于同口径原版 OBS；延续已有目标，不引用用户历史“约159 MB”当精确基线。若无法达成，按 Qt、插件、运行库、业务服务和资源分类继续收敛并给出原因，不伪称通过。

完整功能安装的体积另列硬指标与旧完整 WebOBS 对比。所有额外能力和依赖不能藏到运行后下载、用户目录或扩展目录后从总量中排除。为用户提供：

- 统一 NSIS 安装入口与核心本地监看配置。
- 完整功能安装选项或可验证的离线组件包，原有功能可在同机使用。
- 清楚的已安装/待安装/运行中状态和启停入口，不把功能藏在开发命令中。

去重 Qt、MSVC、FFmpeg/OBS DLL、Web 资源和提取器运行时；不放入 PDB、测试夹具、编译工具与缓存。不同 ABI 的 DLL 不互换。不能未经分析就把上游所有来源插件、CEF、脚本等永久禁用当成产品瘦身；按功能矩阵和安全边界决定核心或可选交付。

可选组件必须版本/ABI匹配、固定来源、校验大小/摘要、可离线安装、可失败恢复；需要可执行内容的组件走正式更新/安装边界，不能接受任意 URL 运行命令。卸载组件前检查消费者并保留用户配置。

## 8. 分阶段执行与阶段完成条件

以下是顺序里程碑，阶段可以迭代，但不得把所有工作都拖成最后一个巨型 PR。每阶段完成后更新台账并继续下一阶段。

### R0：冻结基线与差距清单

交付：最新分支/PR/版本核对、全功能矩阵、依赖与进程图、安装体积口径、已有测试映射、原型成果清单。

完成：每项旧能力有明确迁移位置与验收方法；未验证事实保持未知；选定单一媒体引擎和控制适配方案，记录架构决策。

### R1：真正的 WebOBS 原生产品闭环

实现：首次建账/登录 → 现有设备目录 → 选择摄像机/Profile → 已授权原生 source/scene → 多路监控墙 → 保存 → 正常退出 → 重开登录恢复。

同时解决：产品入口、单实例、native supervisor、control-only 后端、认证前恢复旁路、注销/过期关闭受保护媒体、真实错误 UI。

完成：全新安装包无需手填 OBS RTSP，无诊断 bootstrap/测试 token/手工改配置即可完成流程；真实服务、真实 plugin 和真实 OBS 最终画面联调通过。失败授权零越权媒体 I/O。

### R2：完整 Studio、监控墙和声音

实现：多场景与嵌套、来源管理、草稿/保存、布局编辑、层级裁剪、Preview/Program/转场、多投影/多屏、账号音量偏好、电平/统计叠层、快捷键、窗口/DPI。

完成：不限于五路；保留现有配置范围，多个场景投影来源实例数可解释。保存/重开/切场景与现有 WebUI/远端一致，声音无重复输出。最终像素与动态帧进度测试覆盖黑屏、冻帧、错路、漏路和坐标错误。

### R3：业务能力全量回接与组件化

实现：PTZ/快照/对讲、录像/推流、NVR/归档/证据、事件/检测/规则/通知、go2rtc、网站来源、远程 Web/PWA/Android 兼容、离线工作区与同步、问题中心/备份/诊断。

完成：功能矩阵无“旧能力已删除/仅计划/无实际入口”的遗留；完整功能选项实际安装可用。普通监看不额外启动全量业务进程，开启功能后成本与权限有记录。管理 WebUI 不重复播放本地五路。

### R4：升级迁移与 Windows 生命周期收敛

实现：旧正式版和支持中的开发版 → 新原生版迁移；账号/设备/场景/声音/偏好/录像完整保留；托盘、后台任务、正常退出、崩溃清理；主/子组件升级协调。

完成：Unicode/空格路径、非管理员安装、覆盖安装、重装、默认卸载保留数据、恢复、任务进行中更新、错误包/断网/磁盘不足/失败安装、主进程崩溃均有真实 Windows 自动化证据。保留旧稳定版本的回退安装器和兼容数据副本。

### R5：性能、体积和稳定性收敛

实现：核心和完整安装 footprint、默认/功能启用进程成本、解码/渲染适配器可观察性、同机 OBS 对照工具、最终媒体回归、长稳与故障注入。

完成：可用 Windows runner 上的真实安装/完整产品功能及合成媒体长稳通过；已有环境可测的开销均收集。目标机不可访问时剩余项只允许是最后集中验收所需的真实设备/个人数据指标，不允许拿不到用户设备当成停止 R1–R4 的理由。

### R6：冻结最终 Release 候选

实现：清理开发诊断入口和产品命名、稳定构建模式、NSIS/更新 feed、版本与源码清单、许可证/SBOM、源码包、双语说明、最终验收说明。

完成：用户只需安装一个完整候选，通过产品 UI 使用已有数据和全部功能；不是独立原型、开发 zip、Actions 里散落的组件或要求用户跑 Python 的验收工具集。所有能由 agent/CI完成的工作已通过，已知问题明确列出。

### R7：一次集中实机验收、修复与公开发布

用户在目标机测试冻结候选。agent 提供内置诊断和自动化采样/导出入口，用户不需要重录五路或整理复杂元数据。

收集：实际五路、本人旧数据升级、至少两小时显示稳定性、全屏/多屏/断流恢复、关键业务功能、与 OBS 同机性能、真实安装/更新。

若发现缺陷，读取证据定位并修复，内部完成相关回归，仅提交有针对性的最终候选复验。不能承诺任何缺陷都无需用户复验，也不能把“只测最后版本”理解为忽略最后发现的问题。

通过后执行经审查的稳定发布流程。与验收一致的源码/依赖/配置保持冻结；若为正式 main 发布提交重新构建，必须重新完成二进制身份、安装及相关回归，不能声称重建文件与先前候选逐字节相同。

## 9. 测试策略：让 agent 承担中间验证

### Linux 能完成的部分

- 控制/授权/迁移/配置/布局逻辑和实际服务 API 集成测试；真实 Handler/数据库/Registry 组合，拒绝只用 mock 代替所有后端。
- C++ 契约与真实固定 libobs loader 测试，各自说明覆盖范围；必要时容器验证共享后端，不构建或发布新产品镜像。
- WebUI `pnpm typecheck`、`pnpm build` 和相关真实页面测试。
- 归档、管理、支持诊断、连续性四套使用各自专用配置；Focused Playwright 直接调用 `pnpm exec playwright test -c playwright.local.config.ts --project=chromium <spec>`。
- go2rtc 生命周期/私密配置与 HTTP/WebSocket 代理集成，网站来源三类测试按仓库规定执行。
- 迁移多 schema、失败回退、敏感字段不外泄、打包清单、版本身份与发布审计。

### 必须交给实际 Windows 环境的部分

- MSVC x64 编译/链接、Qt/插件加载、真实 OBS 图、可见窗口最终像素与持续变化。
- 安装后的真实程序，不依赖开发 PATH/Python/Node/VS/WSL/Docker；检查干净环境的运行库与浏览器/组件缺失处理。
- 产品实际登录、建立账号、目录选源、保存/恢复、权限失效、来源旁路、图变更和投影生命周期。
- 实际 NSIS 安装/重装/升级/卸载、旧数据迁移、正常退出与 Job 崩溃清理。
- 中文/空格路径、标准用户、多屏/DPI、锁屏/睡眠唤醒、网络/摄像机重连、音频设备切换。
- 现有 Electron 测试保留用于兼容路径；新原生宿主必须增加同等行为覆盖，不能把 `test:main` 通过当作原生新宿主通过，也不能删除全部旧断言来换绿灯。

### 分层媒体与故障测试

1. 五个可区分的已知动态 H.264/H.265输入：路号、方向、位置、递增时间标记；最终窗口截图验证，不只数 draw callback。
2. 原生 preview、Program、固定场景投影、重排、关闭重开、全屏、多窗口下持续出帧。
3. RTSP TCP及既有受支持传输；认证失败、慢首帧、连接断开、重连、码流改变；错误恢复有预算，不无限重试 401/403。
4. 录像/远程观看同时存在时，本地关闭和来源释放不误停其他任务。
5. 磁盘满、目录不可写、组件缺失、数据库失败、权限撤销、控制服务重启、宿主崩溃；旧数据不损坏，错误可见。
6. 在可用 Windows runner 做至少两小时合成五路长稳，并监测资源增长；NVR等已有更长门禁不缩短。CI合成通过仍不代替目标机真实摄像机/4090 验收。

只对行为风险补充有意义的测试，不为文档或简单可逆 UI 文案堆叠镜像实现测试。修复必须保留能捕获原缺陷的回归。

## 10. 性能与资源验收口径

### 10.1 核心对照

目标：同等五路真实 H.265、画质/FPS/声音/延迟、窗口和输出条件下，产品完整所属 CPU/GPU 成本不高于同口径原版 OBS，并核对内存/显存/功耗与稳定性。

- 固定与宿主相同的 OBS 版本和必要组件；输入分辨率、FPS、码率、传输、Profile、硬解、缓冲、重连、色彩、音轨一致。
- 同一电源/散热/显示器/DPI/GPU偏好；一次只运行一侧，另一侧正常退出。不能并跑抢解码资源。
- 至少三对六轮，交替每对先后顺序，例如 产品→OBS、OBS→产品、产品→OBS。采用生成计划文件，避免历史手册顺序冲突。
- 每轮至少预热180秒、采样1200秒、间隔5秒，保留原始样本与工具开销；对热漂移、后台任务和噪声做复核，不能挑一轮最好结果。
- 统计所有产品所属进程，包括原生宿主、认证/配置服务和功能所需树外进程，不只截图一个 obs64.exe。采样器本身单独记录且双方一致。
- 核对 Intel 与 NVIDIA 的适配器/LUID，分别记录 Video Decode、3D、Copy、显存。硬解“已勾选”不等于逐路实际硬解，不把不同引擎百分比直接相加。
- CPU保留累计时间、按逻辑处理器归一化的时间加权平均、p95和峰值；内存分清working set与private commit，不把共享页重复相加当独占物理内存。
- 同时看最终帧进度、黑屏/冻结/掉帧、声音、端到端延迟和恢复；禁用降帧/静音/遮挡暂停换低开销。
- 记录测量不确定度与可解释预算。目标未满足时定位线程/进程/解码/复制/轮询成本继续优化，不能把轻微超标重新命名为达标。

### 10.2 当前工具的实际限制

`native-host/qualification/collect.py` 和 `--gpu` 是可复用诊断基础，目前声明 `qualified=false`、`strictTotal=false`、`coverageIncomplete=true`。其已观察进程树是下界，原始 GPU 诊断也不是严格总量。不要改常量或删除限制来“通过验收”。

为最终验收增加产品进程清单与归属核对、树外服务覆盖、工具可见的GPU与缺失项、易用采样 UI/脚本。可以继续保留下界报告并附上独立证据，但只有覆盖与测量充分时才能做完整产品的结论；不足时明确尚未证明。

### 10.3 完整功能成本

核心监看与OBS比较；录像、NVR、远程分发、检测、网站来源分别测增量。对OBS无对应功能的业务能力，不声称直接一比一等价，也不把其成本删出完整产品报告。

最终同时交付：核心监看基线、各功能增量、完整功能组合、安装核心/全量体积表和旧WebOBS对比。判断改善依据实际字节和资源数据，不靠“移除了某技术栈”的宣传。

## 11. 安装、升级和稳定更新器

原生宿主不再依赖 Electron 时，现有 electron-updater 不能被假定仍可直接工作。需实现或接入受控原生更新器，保留原有用户体验和验证强度。

- 自动检查/下载的设置与取消、任务阻塞提示继续可用；安装必须用户明确确认，禁用 install-on-quit 和静默替用户升级。
- 只选择精确匹配的正式Windows资产，排除 draft/prerelease/dev/同版/降级；版本按数字比较。
- 保留经验证的 `latest.yml`；原生更新器确实解析/使用或提供兼容桥，不能只有文件没有消费端。
- 下载有超时、重试预算和大小上限；校验完整安装包SHA-512/大小及发行身份。错误/截断/替换包拒绝，重定向与协议策略受控。
- 原生差量可复用时保留并真实测试；若实现首版完整包回退，明确这是传输优化差异，不能宣称已保留差量验收。实际稳定升级主路径必须可用。
- 安装前处理录像、推流、草稿和后台消费者，生成一致性快照、正常停止服务，避免强杀丢数据。
- 主程序、OBS/Qt ABI和可选组件一致升级；网络失败、组件版本不符、安装失败有恢复和可理解的状态。
- 验证旧稳定版→新原生版与新原生版→后续版本两条真实覆盖升级路径。可以使用隔离包标识、私密合成feed和测试数据，不污染用户正式安装与稳定feed。
- 签名沿仓库决定：稳定Windows默认可未签名，明确UNSIGNED，可选显式签名；不能把无签名当作无法继续开发的阻塞。
- 旧用户数据目录与卸载保留行为明确；不因更换宿主或application ID重置账号、录像或升级链。

## 12. 最终交付与发布流程

### 12.1 用户拿到的内容

1. 一个Windows x64完整NSIS安装包，统一入口；核心/完整功能选项清楚，可选组件有可验证离线获取方式。
2. 从旧版本升级/保留数据/失败恢复的简明说明，安装包SHA-256与发行身份。
3. 完整功能清单、实际迁移结果、已知限制、核心与全量体积、实际性能表。
4. 产品内可操作的诊断/采样/脱敏导出；用户无需进入源码目录运行Python或填写复杂元数据。
5. 最终集中验收清单，主要覆盖真实摄像机、本人旧数据与目标机性能；中间CI/打包工作由agent完成。

### 12.2 Release附件与可追溯性

正式安装包、完整摘要、稳定更新元数据、适用blockmap、runtime manifest、依赖锁、SBOM、许可证、产品源码及匹配第三方完整对应源码。OBS/FFmpeg启用组件和上游commit必须准确，不用任意相近源码包替代。

上传之前验证实际包内版本、清单和安装回执；附件不可覆盖，开发包不可重命名为稳定包。更新元数据最后验证指向正确资产，防止尚未齐备就让用户自动取到错误版本。

### 12.3 与现有发布流程衔接
