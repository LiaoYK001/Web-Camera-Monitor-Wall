# 升级、备份与恢复 / Upgrade, backup and recovery

本文适用于 v4 开发的操作准备，不代表 v4 候选已合格或已发布。最新公开产品说明见 [v3.5](release-notes-v3.5.md)；当前重启/异常退出修复保留到 v4，不操作 v3.5 热修。具体平台契约优先于本文。

## 1. 变更之前 / Before changing anything

1. 记录实际安装版本、源码 revision/镜像 digest、部署方式及当前数据位置，不能把 WebUI 版本当作 Electron/APK/后端版本。
2. 使用产品备份入口或正常停服后的应用一致性备份。不要复制正在写入的 SQLite/WAL 作为一致快照；分别保护配置、账号、密钥、录像和外部存储。
3. 完整配置备份含敏感数据；离线布局 JSON 是脱敏迁移包，不能代替数据库/密钥/录像备份。备份和恢复密钥需仓库外加密保管，并验证可恢复。
4. 核对候选摘要、大小、身份与来源，保留上一匹配安装包/镜像和快照；开发包不能接入稳定更新源。
5. 完成或取消未保存修改、前端下载和证据任务。请求超时可能已在服务端完成；先刷新核对，不能盲目再次创建任务、账号或节点授权。

Back up first, preserve the version-to-snapshot mapping, and treat lost responses as unknown outcomes. A successful download or unit test is not an installed-upgrade qualification.

## 2. 账号和旧环境 / Accounts and legacy environment

当前 [Compose](../compose.yaml) 默认启用账号/RBAC 控制面并关闭旧式 Basic Auth；[环境示例](../.env.example)与其一致。首次部署通过 WebUI 创建管理员，没有预置用户名/密码。认证控制面也服务于本地开发，不意味着打开了集群的外部管理监听。

- **已有部署不自动修改**：旧的本机环境文件若显式设为 `WEBOBS_CLUSTER_ENABLED=false`，仍会覆盖默认值。先备份，检查所用 Compose overlay 和旧凭据模式，再显式启用账号控制面；不要覆盖整个环境文件。
- **保留旧数据**：继续使用原 Compose project、私有配置卷和录像挂载。不需要删卷、清空浏览器数据或重建摄像机目录来启用账号。
- **首次管理员**：只在受信回环入口完成；已有管理员时应登录而不是重新注册。账号密码使用 Argon2id；旧文件型 Basic 凭据不是自动创建的数据库账号。
- **失败时**：区分后端不可达、认证服务不可用、会话到期与无权限；检查健康/就绪和服务日志的脱敏摘要。不要通过关闭认证或放宽 Origin 修复错误。
- **远程连接**：LAN/跨设备访问需 HTTPS、正确 Origin/主机、证书信任和媒体端口；不要把基础本地 HTTP/首次设置直接暴露到不受信网络。

## 3. 容器 / Container

沿用原项目、overlay 和卷，先按[容器部署的备份/升级章节](docker-deployment.md#9-一致性备份与恢复)操作。正常停止应保留足够 grace period 让录像封装；禁止以 `down --volumes` 作为日常停止或修复方式。

升级失败需检查候选状态及升级守卫记录，使用匹配的旧镜像/快照恢复；不能仅换旧镜像后继续使用可能已迁移的新数据库。重启恢复的实现和证据边界见[容器重启](container-restart-recovery.md)。不要把历史 v3.5 轻量热修示例当作当前发布步骤。

## 4. Windows x64 / Windows desktop

[完整契约](windows-desktop.md#投影局域网与备份恢复)。在桌面入口创建完整配置备份会正常停服、取得一致性快照和加密备份后恢复运行；录像媒体不包含在配置备份内。默认数据在当前用户本机目录，DPAPI 密钥有用户/机器边界，不能承诺直接复制目录跨设备恢复。

更新保留大小/SHA-512 校验、显式安装确认、正常停服、快照和回退。启动失败时先安装记录的对应旧版本，再恢复匹配快照；恢复入口校验记录和摘要。当前 unsigned 是发行策略，不能把未签名开发 NSIS 放进稳定 feed。实际干净系统与版本连续安装仍待候选资格验收。

## 5. Android / Independent Android client

[更新契约](android-updates.md)要求实际已安装 APK 的包名/签名、递增版本码、完整大小/SHA-256 校验和系统确认。开发签名/一次性测试密钥不等于稳定身份。正式候选使用仓库外持久自签密钥并备份；不同密钥不能直接覆盖安装。

不要为更新测试卸载、清除或替换现有产品数据；使用独立验收包。保留连接设置、会话及偏好，更新权限/磁盘/网络失败应保留可恢复状态。模拟器与版本契约测试不能替代生产包/公开源/ARM 真机的实际安装验收。

## 6. 浏览器 / Browser and PWA

安全更新及时替换旧 Worker 并重载，不能无限延迟旧认证门。已提交服务器的数据、既有加密本机档案和持久同步队列不同于当前页尚未保存的输入；后者不能保证自动恢复。更新前主动保存安全布局/完成操作；恢复后先确认会话、权限与任务列表，切勿自动重放管理 POST。

录像和持久证据任务属于后端，关闭页面不等于停止录像或取消任务；导出状态要从当前账号查询。投影恢复必须重新经过认证并保持固定 Scene，不应静默切到其他场景。

## 7. 记录而不是推定 / Evidence, not assumptions

每次实际升级单独记录源码/产物身份、环境、数据保留、回退和故障结果。当前非真机改进不完成同 revision 全候选、真实升级、真机、LAN 或长期运行门禁；未测项继续保留在 [v4 矩阵](v4-readiness.md)。
